## 2. 任务一：Qbar 文件图标

### 2.1 问题原因

`IconCache.FromFile` 原实现按扩展名三分：

1. `.exe/.dll` → `ExtractIconEx`
2. `.lnk/.url/.appref-ms/.cpl/.msc` → `SHGetFileInfo`
3. **其余全部** → `FromImageFile`（`BitmapImage` 解码）

PDF 不属第 1、2 类，走第 3 类解码必然抛异常 → `null` → `QbarItem` 退化成内置字形。同理，未知扩展名、无扩展名、网络路径、UWP 也全部落到这条错误分支。此外没有尺寸/DPI 参数、没有叠加图标、全部同步执行（大目录会卡列表）。

### 2.2 修改方案

**取图链（`ShellIcons.cs`）**

1. 快捷方式（`.lnk/.url/.appref-ms/.pif`）：`SHGetFileInfo(SHGFI_ICON|SHGFI_LINKOVERLAY|SHGFI_LARGEICON)`
   —— 实测 `SHGFI_OVERLAYINDEX` 在本机对真实 .lnk 返回 0、`IImageList.GetIcon(1..6)` 只给文件类型图，只有这条出口带箭头（理由写在 `ShellIcons.cs:748-762`）。
2. 其余：`IShellItemImageFactory::GetImage(SIIGBF_ICONONLY|SIIGBF_BIGGERSIZEOK|SIIGBF_RESIZETOFIT)` —— 尊重当前默认关联（PDF 的 Edge/Acrobat/Reader 由系统自己决定）。
3. 前两步失败：`SHGetFileInfo(SHGFI_SYSICONINDEX)` + `SHGetImageList(SHIL_SMALL/LARGE/EXTRALARGE/JUMBO)` + `IImageList::GetIcon(ILD_TRANSPARENT)`。
4. 三条都失败：**返回 null 并 `WarnOnce` 记日志**，由上层决定（不再按扩展名猜内置图）。

**尺寸与 DPI**：`PickPixels(dip, dpiScale)` 按 `{16,24,32,48,64,96,256}` 向上取档；`QbarItem.IconDip=28`，DPI 从可见 Qbar 的 `VisualTreeHelper.GetDpi().DpiScaleX` 取，取不到退 `ShellIcons.SystemDpiScale()`。28 DIP 在 100%/125%/150%/200% 下分别取 32/48/48/64，与资源管理器同档。

**缓存键**（`ShellIcons.cs:468-471` 附近）：

```
normPath \u0001 像素尺寸 \u0001 DPI 比例 \u0001 文件 LastWriteTimeUtc.Ticks \u0001 关联版本戳
```

- 网络路径不取 `LastWriteTime`（记 0，避免枚举时打网络）；本地文件的时间戳另有 4 秒 TTL 缓存（`StampTtlMs=4_000`），负结果缓存 60 秒（`NegativeTtlMs=60_000`）；
- **关联版本戳**：读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\<ext>\UserChoice` 与 `HKCR\<ProgId>\DefaultIcon` 的注册表 `LastWriteTime`（`RegQueryInfoKey` 12 参，7 个 `out _` + `out long lastWrite`）拼进键 → 改默认程序后旧图标自然不再命中；
- `Invalidate(reason)` 递增 `_epoch`，旧 epoch 的在途结果直接丢弃；`SystemEvents.UserPreferenceChanged`（DPI/主题/关联变更）触发 `Invalidate`；缓存上限 512 条（`CacheCap=512`，超过整表清空）。

**异步与非阻塞**：单条后台 STA 线程 + `BlockingCollection` 队列；同 key 的并发请求用 `Pending.GetOrAdd` 合并；网络路径另起短命 STA 线程 `Join(400ms)`，探不到就放弃（不拖住队列）；`QbarItem.TryResolveIcon` 先纯字典命中（不碰磁盘），未命中才异步，回调 `Dispatcher.BeginInvoke(SetIcon)`。权限不足/文件已删/路径过长/网络盘离线一律走 `catch` → null，列表不卡、不报错。

### 2.6 已知限制

- 快捷方式固定取系统大图标档（32×DPI），96/256 档由 `Image` 拉伸，边缘略软（Shell 只在这条出口合成箭头）。
- `shell:` 命名空间项与部分 UWP 包，`GetImage` 可能失败并落到更小档。
- 网络路径 400ms 探不到就返回 null（只保证不卡 UI，不保证离线盘出图）。
- 依赖 `shell32` 未文档化导出序号（`#722/#727`），Windows 大版本升级需回归。

## 3. 任务二：按住拖拽（以 AltDrag v1.1 为基准）

### 3.1 模块边界与调用链

`Modules/HoldDrag/**`（钩子/状态机/几何）+ `Core/HoldDrag/**`（服务、E2E）。**与 Qbar 无耦合**：Qbar 只通过 `HoldDragHoldsTrigger()` 让路，方向是单向的。

## 4. 任务三：Qbar 网络搜索联想

### 4.1 交互与状态机

显示条件（四道闸，`TryGetSuggestionContext`）：Qbar 可见且未关闭、`SuggestEnabled`、当前 chip 是 `ChipKind.Search` 且不是程序名（`QbarService.LooksLikeProgram`）、输入非空。→ Web 模式（直接敲网址）、Run 模式、本地程序名都不发请求。

时序：输入 → `ScheduleSuggestions` 立即隐藏旧候选 → 停旧定时器、`cts.Cancel`、`_suggestSeq++` → 250ms 防抖 → `OnSuggestTimerTick` 读当前设置并 `Clamp` → 缓存命中直接显示（按新 max 截断）→ 否则 `seq=++_suggestSeq`，`CancelAfter(timeout)`，`await Create(engine,max).QueryAsync(...)` → 回来 `if (seq != _suggestSeq) return` 丢过期 → 显示前再复核 `engine+keyword`。

键盘：窗口级 Esc 三层（文件菜单 → 联想 → 面板）；↑↓ 只在联想可见时移动 `SuggestList.SelectedIndex` 并 `Handled`；Enter **只有选中联想时**才 `AcceptSuggestion`，否则走原 `CompleteSelected/ExecuteSelected`（搜原文）。

### 4.2 三个联想源

| 引擎 | 端点 | 解析 |
| --- | --- | --- |
| 百度 | `suggestion.baidu.com/su?wd=…&cb=` | 先按 UTF-8 读，失败注册 `CodePagesEncodingProvider` 按 **GB18030** 解码；手写扫描器只在字符串外认 `s:`，不按第一个 `]` 截断（关键词里带 `s:[` 也不误命中） |
| 谷歌 | `suggestqueries.google.com/complete/search?client=firefox&hl=zh-CN&q=` | JSON 数组，`JsonDocument` 反转义 |
| 必应 | `api.bing.com/osjson.aspx` → `cn.bing.com/osjson.aspx` → `api.bing.com/qsonhs.aspx?type=cb&cb=cb&q=` | 前两级本机实测多次 **204 空正文**；第三级 JSONP 截首个 `{` 到末个 `}` 取 `AS.Results[].Suggests[].Txt` |

`SuggestionEngines`：`auto/baidu/google/bing`；`auto` 按**当前搜索 URL 模板的 Host** 判（baidu. / google. / g.cn / bing.），认不出兜底 Bing。`SuggestionCache`：key = `engine + "\n" + keyword.Trim().ToLowerInvariant()`，容量 256、只缓存非空、TTL 0 = 不缓存、`Prune` 清过期。

### 4.3 设置项（持久化）

`QbarOptions`：`SuggestEnabled=true`、`SuggestEngine="auto"`、`SuggestMax=6`、`SuggestTimeoutMs=800`、`SuggestCacheMinutes=10`。设置页「搜索联想」卡在**下一次输入时**生效（文案已写明），保存走既有 `SaveSettings`。切换搜索引擎后 chip 变了 → 上下文重算 → 旧候选隐藏 + 按新引擎重新请求。

### 4.4 关键代码

