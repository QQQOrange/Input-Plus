# Input Plus 鼠标手势"时灵时不灵"诊断与修复报告

日期：2026-11-18　版本：5.15.0　目标：同一手势在 WGestures 2 能触发、在 Input Plus（下称 KE）经常触发不了

---

## 一、结论先说

1. **不是阈值太严，也不是 128 点上限或点数比被卡。** 干净输入下旧引擎自己画自己 129/135 次命中（95%），说明形状比对本身没坏。
2. **真正的原因是"判定时机"不一样。**
   - WGestures 2 是**边画边判**：每来一个鼠标点，就拿"已经画出来的这一段"去比模板，一旦前缀命中就当场执行（反编译源码 A/m.cs:478-560）。
   - KE 只在**松手那一刻**用**整条轨迹**比一次（GestureService.Finish → PickStroke → GestureEngine.Match）。
   - 人收笔时手会带一下：回勾、过冲、甩尾十来像素。这一段在 (累计弧长 s, 方向角 θ) 距离里被放大，整条距离直接顶到 DP 的无解上限 0.2（阈值才 0.05），于是判未命中。
   - 证据：真实日志 app.log 里 **87 次未命中，偏差全是 1.000**，没有任何 0.9x 的中间态 —— 这正是"距离顶到上限"的指纹，而"差一点点"不会是同一个数。
3. **量化**（1800 组真实手感样本：8ms 轮询 + 2px 量化 + 手抖 + 弓形 + 速度曲线 + 收笔回勾）：
   - 整条比（改前）：判对 56.0%，未识别 34.2%
   - 切掉尾巴再比：判对 85.4%，未识别 8.3%
   - 收笔带 15px 回勾的一组：命中率 47.4% → 90% 以上
   - 这套模拟器算出的总体命中率（70.6%）与真实日志的 202/289 = 69.9% 几乎完全吻合，所以可信。
4. 次要因素：小尺寸手势吃亏。KE 会把轨迹归一化到 1000 单位，80px 的手势放大约 12 倍，坐标取整和手抖一起被放大；而 RDP 简化阈值写成 `Math.Max(0.75, Extent(even)*0.004)`，even 已归一化，所以**恒等于 4.0**，噪声折点被保留。实测 80px 手势命中率只有 32.8%（300px 就有 91.9%）。这不是主因，但让"画得小"更容易失败。

## 二、改了什么（UI 一行没动）

### 1. 松手结算补上"尾巴容错"（核心）

`src/InputPlus/Core/Gestures/GestureEngine.cs`

- 新增 `MatchRelease(bucket, points, opts)`：先把收笔那 10 来像素切掉再比，这是 WG2 实时语义在"松手结算"上的等价实现。
  - 尾巴长度 = `min(max(16px, 弧长×4%), 弧长×25%)`；切完不够 3 点就退回整条比。
- 新增 `TrimTail()`：按弧长从尾部截断，截在段中间会插值补点。
- 新增"整条完美优先"规则：切尾版命中后，若**整条**距离 ≤ 0.2×阈值（即几乎一模一样）且切尾结果比它差 0.3 分以上，则采信整条。
  - 这条规则是实测案例逼出来的：任务管理器（右键 ↑↓↑↓）整条距离 0.0000，切尾后反而只跟 QQ邮箱 像（0.047），旧逻辑会把 0.047 的答案盖在 0.0000 上。
- `Match()` 本体、阈值、歧义容差、闭环容错、长候选守卫（AwaitsLonger）**一律没改**。

调用点：`UI/GestureService.cs:1453`（松手结算 PickStroke）、`Core/Gestures/GestureProbe.cs`（探针按松手口径测）。预览、立即执行、自检仍走 `Match`。

### 2. 探针保真（此前 83% 的"撞车"是假报）

`Core/Gestures/GestureProbe.cs`

- 分桶原来看"作用域 + 全局 + 非通配"，**不看触发键**，于是"右键的 →"和"滚轮的 →"被当成同台竞争，撞车表一片 0.0000。
- 现在按 Button、Chord 分桶，并新增 `RuntimeMatch`（先应用专属桶、再全局桶，命中即返回），与运行期 `GestureService.Candidates/PickStroke` 一致。

### 3. 去重判定收紧（否则启动时静默少 4 条）

`Core/Gestures/GestureIdentity.cs`

- 原来只看"方向串"是否相同，于是"关闭 ↓→"和"休眠 ↓→"（其实差 0.0071，能量出来）被当成重复删掉一条。
- 现在：点阵逐点一致才算重复，否则形状差要 ≤ 0.2%（1000 空间）。

### 4. 新增命令行开关，用来整表替换手势

- 新文件 `Core/Gestures/GestureImport.cs`，入口 `--gesture-import <文件> [--keep]`（默认先清空再导入），支持 `.wg28bw`（zip，内部 gestures.json）或裸 gestures.json；报告写 `数据目录\gesture-import.txt`。
- `Core/CliFlags.cs` 登记开关与用法，`App.xaml.cs` 分支派发。

## 三、手势表：已删光旧手势，换成 WG2 的

- 执行：`InputPlus.exe --gesture-import "<配置目录>\我的手势.wg28bw"`
- 替换前 60 条 → 已清空 → **导入 64 条**（WG2 配置里 74 条意图，16 条翻译不了被跳过）→ 启动去重后 **61 条**（56 笔画 + 4 滚轮 + 1 角落）。
- 跳过的 16 条主要是：只有按键没有笔画的纯点击、以及 Script 类型（除"打开设置"以外的脚本 KE 不支持）。
- 启动时再删掉 3 条（因为触发方式与形状完全相同，只能留一条）：
  - **刷新（右键+左键 ↓）** 与 **粘贴并 Enter（右键+左键 ↓）** 在 WG2 配置里本身就是同一笔（原始数据 P 都是 [1409,594,1409,896]），KE 无法区分，保留先出现的"粘贴并 Enter"。
  - **放大 / 缩小** 在 WG2 里是"右键 + 一小段笔画 ↑ + 滚轮"的组合，KE 的手势模型表达不了"笔画接滚轮"，导入后与"上一标签 / 下一标签"（右键 + 滚轮）撞车，被按重复去掉。

## 五、还剩两处需要你拍板

1. **刷新（右键+左键 ↓）** 现在被"粘贴并 Enter"占着，永远触发不了。要用刷新，建议在 KE 里把它的触发方式改成别的（例如右键+中键 ↓），或直接删掉。
2. **放大 / 缩小**（右键 + 小笔画 + 滚轮）KE 表达不了，已随去重消失。要保留请在 KE 里给它们单独绑一个能表达的触发方式。

## 六、回滚与备份

- 部署快照（换 exe 前的用户数据）：`<安装目录>\_deploy-snapshots\<时间戳>`

- 重新导入原配置：`InputPlus.exe --gesture-import "<配置目录>\我的手势.wg28bw"`（默认整表替换；加 `--keep` 是追加）
